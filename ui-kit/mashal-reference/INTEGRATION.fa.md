# اتصال کتابخانه به مشعل فعلی

این پوشه کتابخانهٔ ظاهر است؛ جایگزین‌کردن نسخهٔ کل برنامه یا اجرای migration برای استفاده از آن لازم نیست. هیچ فایل Controller، Service، Entity یا Migration در این کار تغییر نکرده است. کتابخانه هنوز به‌صورت سراسری روی صفحات فعال نشده است.

## مسیر پیاده‌سازی

۱. پوشه را در یک شاخهٔ مخصوص UI روی سورس دقیق نسخهٔ نصب‌شده قرار بدهید. برای دریافت این پوشه، کل نسخهٔ جدید برنامه را روی production جایگزین نکنید. اصلاحیه‌های COGS و ContractPnl و افزونه‌های نصب‌شده باید حفظ شوند.

۲. فایل‌های `tokens.css`، `components.css`، `behaviors.js` و `assets/` را در `wwwroot/mashal-kit/` کپی کنید. `gallery.js` و `specimen.js` و گالری و فایل‌های مرجع برای محیط production لازم نیستند. مسیر fontها نسبت به tokens.css و مسیر فونت آیکن‌ها نسبت به CSS آیکن‌ها حفظ شود. نمونه‌های HTML، مسیر asset را نسبت به گالری دارند؛ هنگام استفادهٔ Razor، `src="assets/..."` به `src="~/mashal-kit/assets/..."` تبدیل شود.

۳. یک فرم آزمایشی را با پوستهٔ اختیاری فعال کنید؛ ابتدا کنترل‌های واقعی فعلی را نگه دارید:

```html
<link rel="stylesheet" href="~/mashal-kit/assets/bootstrap-icons.min.css" />
<link rel="stylesheet" href="~/mashal-kit/tokens.css" />
<link rel="stylesheet" href="~/mashal-kit/components.css" />
<link rel="stylesheet" href="~/mashal-kit/adapter.css" />

<section data-mr-theme="light" data-mr-adapt>
    @* فرم واقعی فعلی، بدون تغییر asp-for/name/id/data-* *@
</section>
```

`adapter.css` فقط ظاهر کنترل‌های موجود را تغییر می‌دهد. الگوی جدید HTML را کورکورانه جایگزین کنترل ترکیبی تاریخ/شخص/بانک نکنید؛ این کنترل‌ها رفتار و hookهای خاص خود را دارند. فایل behaviors.js فقط در صورت استفاده از اجزای جدید بارگذاری شود و از `data-mr-action`های متعلق به کتابخانه استفاده می‌کند.

## نقاط مشترک واقعی پروژه

| خانواده | محل فعلی | اجزای این کتابخانه |
|---|---|---|
| پوسته و ناوبری | `Views/Shared/_Layout.cshtml` | C01 تا C05، C14، C17، C37 |
| منوی داخلی تنظیمات | `Views/Shared/_MashalSettingsNav.cshtml` در نسخهٔ جدید | C06؛ در نسخهٔ قدیمی به‌عنوان partial ظاهری جدا اضافه شود |
| عنوان فرم | `Views/Shared/Components/Ak/_AkPageHeader.cshtml` | C05 |
| عملیات فرم | `Views/Shared/Components/Ak/_AkFooterActions.cshtml` | C07، C08، C34 |
| پوستهٔ ایجاد و ویرایش | `Views/Shared/_CreatePageShell.cshtml` و `_EditPageShell.cshtml` | tokens و adapter؛ فرم و antiforgery حفظ شوند |
| فرم‌های مشترک | `.ak-input`، `.form-control`، `.form-select` و `.ak-label` | C10 تا C13، C16، C18، C19 و C36 |
| جدول | `.ak-table` | C20 فقط الگوی سرستون؛ ردیف و paging فعلی حفظ شوند |
| کارت و خلاصه | partialهای `Views/Shared/Partials/` | C23 تا C31؛ داده از مدل فعلی بماند |
| مودال | پوستهٔ مودال فعلی؛ یا dialog جدید در الگوی مستقل | C32، C33؛ دو سیستم مدیریت modal هم‌زمان روی یک عنصر نصب نشوند |

۴. در partialهای مشترک، فقط کلاس‌های ظاهر و ساختار غیرمالی را عوض کنید. `asp-for`، `asp-action`، `name`، `id`، `data-*`، validation، readonly/disabled، نقش‌ها و مجوزها، توکن ضدجعل و مالکیت fieldset ثابت بمانند. دکمهٔ نمونه با `type="button"` را جایگزین submit واقعی نکنید.

۵. C23 تا C27 عمداً شامل ارقام نمونه هستند. در نسخهٔ واقعی همان دادهٔ مدل را bind کنید؛ هیچ محاسبه‌ای از کتابخانه اضافه نکنید. شمارش‌ها و نمودارها هم از دادهٔ واقعی فعلی بیایند. گزینه‌های مالی نشان‌داده‌شده در مرجع به معنای پشتیبانی backend مشعل از آن‌ها نیستند.

۶. فقط صفحه‌ای که opt-in شده باید تغییر کند. بعد از تأیید فرم، کلاس‌ها و tokenهای مشترک را مرحله‌ای به سایر صفحات برسانید. هر تغییر مشترک همهٔ مصرف‌کنندگان همان partial را تحت تأثیر می‌گذارد؛ آن صفحات باید بررسی شوند.

## بررسی پیش از انتشار

- FormData و فیلدهای ارسالی قبل/بعد یکسان بمانند؛ به‌ویژه حالت نقد، بانک، صراف و فیلدهای disabled.
- ورود، تقویم، جستجوی شخص/بانک، نقش‌ها، submit و خطای اعتبارسنجی در همان فرم واقعی بررسی شوند.
- سود P002، CompanyOverview، COGS، مانده‌ها و دفتر کل با نسخهٔ نصب‌شده تغییر نکنند.
- migration جدید، seed، یا تغییر دیتابیس برای این کتابخانه لازم نیست و نباید انجام شود.
- حالت موبایل، صفحه‌کلید، focus و reduced motion بررسی شوند.
- انتشار نهایی فقط برای دامنهٔ هدف و پس از بکاپ، با روش بازگشت مستقل انجام شود.

## تغییر ظاهر کل سیستم از یک محل

رنگ اصلی: `--mr-primary`؛ عرض سایدبار: `--mr-sidebar-width`؛ ارتفاع بالای صفحه: `--mr-header-height`؛ ارتفاع فیلد: `--mr-field-height`؛ فونت: `--mr-font`؛ فاصله‌ها: `--mr-space-*`. تغییر token فقط روی اجزایی اثر دارد که به کتابخانه متصل شده‌اند؛ صفحات قدیمی خودبه‌خود و بدون اتصال تغییر نمی‌کنند.
