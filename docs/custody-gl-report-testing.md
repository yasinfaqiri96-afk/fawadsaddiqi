# راپور تطبیق دفتر کل امانی

مسیر `Custody/LedgerReport` با مجوز `ManageData` فقط دفتر کل موجود و سطرهای عملیاتی امانی را می‌خواند. هیچ ژورنال، سند جبرانی، پرداخت یا دفتر موازی ایجاد نمی‌کند.

- حساب وجوه مالک (2600، طبق نقشه حساب شرکت) برای هر هویت جدا تفکیک می‌شود: بستانکار بدهی، بدهکار طلب شرکت. جمع‌کردن پس از تفکیک است؛ مالکان مختلف تهاتر نمی‌شوند.
- حساب منتظر وصول (1210، طبق نقشه) کاهندهٔ دریافتنی مشتری نمایندگی است. دریافتنی خالص نمایندگی برای شرکت جدا نمایش داده می‌شود.
- مانده GL و دفتر عملیاتی هر مالک، سطرهای فاقد هویت و اسناد فعال بدون ژورنال نمایش داده می‌شوند. حساب خاموش، نقشه ناقص/نامعتبر و ارز عملیاتی غیر USD مانع تأیید تطبیق‌اند؛ نرخ حدسی استفاده نمی‌شود.
- تاریخ پایان روز روی تاریخ حسابداری ژورنال و تاریخ سطر عملیاتی اعمال می‌شود. راپور، جایگزین بازسازی وضعیت تاریخی سند یا بیلانس عمومی شرکت نیست.
- دامنه فعلی حساب مالی مالک، مشتری و فروشنده است. شریک و شرکت در نگهداری پشتیبانی می‌شوند؛ هویت مالی مشترک و سایر قابلیت‌های باز باید جدا تکمیل شوند.

تست PostgreSQL در `CustodySalePostgresTests` برای تفکیک مالکان بدهکار/بستانکار، علامت مالک مشتری، تاریخ پایان و تشخیص سند تاریخی فاقد GL نوشته شده است. نتیجه اجرای واقعی در مستند پیشرفت ثبت می‌شود.

تست مرورگر `scripts/qa/custody-gl-report-browser.cjs` به همان fixture ساختگی و متغیرهای ورود [custody-conversion-testing.md](custody-conversion-testing.md) نیاز دارد. دفتر کل fixture خاموش است؛ هشدار صریح، شمار اسناد ثابت و عرض‌های390/768/1440 بررسی می‌شوند. هیچ اعتبارنامه یا خروجی `/tmp` وارد Git نمی‌شود.
